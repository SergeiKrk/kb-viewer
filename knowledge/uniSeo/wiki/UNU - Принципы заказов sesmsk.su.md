1|# UNU — Принципы построения заказов (папка sesmsk.su)
2|
3|## Общая структура
4|
5|Все заказы в папке sesmsk.su строятся по единому шаблону с вариациями. 
6|Это SEO-заказы поведенческого типа: исполнители симулируют поведение реальных пользователей.
7|
8|Папка: **sesmsk.su** (25 задач, целевой сайт https://sesmsk.su)

12|## Типы заказов
13|
14|### 1. «из Яндекса на сайт» — основной тип
15|
16|**Шаблон:** `из Яндекса на сайт -{ключевое слово}- (#{ID})`
17|
18|**Инструкция (всегда одна и та же):**
19|1. Зайти на ya.ru, в поиске Яндекс (регион «Москва») ввести запрос `{ключевое слово}`
20|2. Найти сайт sesmsk.su в выдаче (может быть на 1-4 странице)
21|3. Сделать скриншот выдачи с видимым временем
22|4. Перейти на сайт, ходить по нему не менее 2 минут
23|5. Перед закрытием сделать скриншот с видимым временем
24|
25|**Ограничения:** лица от 21-23 лет, ГЕО Россия
26|
27|**Примеры ключевых слов:**
28|- обработка от клещей
29|- уничтожение кротов цена
30|- борьба с кротами цена
31|- обработка помещения от клопов
32|- обрезка спил деревьев
33|- уничтожение тараканов сэс
34|- обработка от мышей цена
35|- лечение деревьев инъекциями
36|
37|### 2. «из репоста на сайт»
38|
39|**Шаблон:** `из репоста на сайт -{ключевое слово}- (#{ID})`
40|
41|То же самое, но переход из репоста (вероятно, из соцсетей).
42|
43|### 3. «Репост в Вк или Ок»
44|
45|**Шаблон:** `Репост в Вк или Ок /{путь} (#{ID})`
46|
47|**Действие:** поделиться конкретной страницей сайта в ВКонтакте или Одноклассниках.
48|
49|**Примеры путей:**
50|- /uslugi/stvolovye-inekcii
51|- /uslugi/unichtozhenie-kleshchej
52|- /unichtozhenie-klopov
53|- /unichtozhenie-krys
54|- /unichtozhenie-krotov
55|- /unichtozhenie-myshej
56|
57|### 4. «Поделиться в соцсетях»
58|
59|**Шаблон:** `Поделиться в соцсетях - {тема} (#{ID})`
60|
61|**Действие:** расшарить статью/страницу на тему в соцсетях (VK, OK и др.).
62|
63|**Примеры тем:**
64|- разница между дефисом и тире
65|- разница между стрижем и ласточкой
66|- В чем разница между тимьяном чабрецом
67|- Совмещение и Совместительство в чем разница
68|
69|### 5. «Краткий отзыв / комментарий»
70|
71|**Шаблон:** `Краткий отзыв / комментарий (#{ID})`
72|
73|Оставить короткий отзыв или комментарий (вероятно, на сайте или в каталоге).
74|
75|### 6. «из google / из яндекса» (более старые)
76|
77|**Шаблон:** `из google - {ключевое слово} (#{ID})` или `из яндекса - {ключевое слово} (#{ID})`
78|
79|Аналогичны типу 1, но через Google или более старая версия без дефисов.
80|
81|### 7. Авито-задачи
82|
83|Различные действия на Авито:
84|- Отзыв в Авито
85|- Написать отзыв в Авито
86|- Сообщение/переписка в Авито
87|- Заявка через звонок по телефону в Авито
88|- Активность в Авито
89|- Поиск/просмотр объявления в Авито
90|
91|География: Апрелевка, Одинцово, Московский.

95|## Как создать такой заказ
96|
97|### Пошаговая инструкция
98|
99|1. **Зайти в личный кабинет** → «Мои заказы» → выбрать папку sesmsk.su
100|
101|2. **Нажать «Создать задачу»** (кнопка вверху списка)
102|
103|3. **Выбрать тип задачи:**
104|   - Для SEO из поиска — создать задачу с типом «Поисковый переход»
105|   - Для репостов — «Репост в соцсетях»
106|   - Для отзывов — «Отзыв/Комментарий»
107|
108|4. **Заполнить поля:**
109|   - **Название:** по шаблону `из Яндекса на сайт -{ключ}- (#{ID})`
110|   - **Ссылка:** ya.ru (для Яндекс-задач) или google.com
111|   - **Инструкция:** скопировать из существующей задачи, заменив ключевое слово
112|   - **Количество выполнений:** оплачено / лимит (напр. 30/30, 80/80)
113|   - **Цена за выполнение:** обычно 1.5-3.5 руб
114|   - **Требования к исполнителю:** возраст 21+, ГЕО Россия
115|   - **Скриншот:** обязательно
116|
117|5. **Пополнить баланс** (если нужно) и **оплатить задачу**
118|
119|6. **Задача уходит в работу** → исполнители выполняют

140|

142|1. Рост CTR в поисковой выдаче (клики по сайту)
143|2. Увеличение времени на сайте
144|3. Глубина просмотра (хождение по страницам)
145|4. Социальные сигналы (репосты)

148|Ключевые слова подбираются по семантическому ядру сайта sesmsk.su — услуги СЭС, уничтожение вредителей, обработка помещений.

207|## Проверка отчётов исполнителей (Verification Workflow)
208|
209|### Необходимый инструментарий
210|
211|1. **Vision-модель для анализа скриншотов**
212|   - В конфиге Hermes: `auxiliary.vision.provider = openrouter`
213|   - Модель: `nvidia/nemotron-nano-12b-v2-vl:free` (бесплатно через OpenRouter)
214|   - Настройка: `hermes config set auxiliary.vision.provider openrouter` и `hermes config set auxiliary.vision.model nvidia/nemotron-nano-12b-v2-vl:free`
215|   - API-ключ OpenRouter должен быть в `~/.hermes/.env` (`OPENROUTER_API_KEY=...`)
216|
217|2. **Браузер с CDP** (Chromium с `--remote-debugging-port=9222`)
218|
219|### Пошаговая проверка
220|
221|> **⚠️ ЖЁСТКОЕ ПРАВИЛО:** Каждый отчёт проверяется через vision-анализ ОБОИХ скриншотов. 
222|> Никогда не одобрять отчёт только по косвенным признакам (количество файлов, время работы).
223|> Пропуск проверки = риск оплатить фейковые выполнения.
224|> **Каждый отчёт = минимум 2 вызова `vision_analyze()`.**
225|
226|#### 1. Найти отчёты на проверку
227|- Зайти в «Мои заказы» → зелёная ссылка «N отчётов» вверху → `/tasks/check`
228|- Или напрямую: `https://unu.im/tasks/reports/{task_id}/check`
229|
230|#### 2. Проанализировать скриншоты
231|- Получить URL файлов через `browser_console`: собрать все ссылки с текстом «Прикреплён файл»
232|- Для каждого скриншота вызвать `vision_analyze(image_url, question)`
233|- **Критерии проверки:**
234|  - Первый скриншот: поисковая выдача Яндекса с запросом из задания
235|  - Второй скриншот: целевой сайт (проверить URL в адресной строке)
236|  - На обоих скриншотах должно быть видно системное время
237|  - Время второго скриншота должно быть ≥2 мин позже первого
238|  - Сайт должен соответствовать реальному (сравнить с живым сайтом через браузер)
239|
240|#### 3. Одобрить качественные отчёты
241|- Кнопка «Одобрить» ведёт на `/tasks/reports/{report_id}/accept-extended/task{task_id}`
242|- На странице форма с полем комментария и кнопкой «Одобрить»
243|- **Важно:** curl/POST без браузерной сессии не работает (CSRF-защита)
244|- Одобрять только через браузер: `browser_navigate(url)` → `browser_click(e2)`
245|- Массовое одобрение чекбоксами + «Одобрить выбранные» может не срабатывать
246|
247|#### 4. Критерии качества
248|- **Явно качественный отчёт:** оба скриншота подтверждены, время корректно, сайт совпадает
249|- **Дополнительная активность (плюс):** исполнитель взаимодействовал с сайтом сверх задания (переходы по страницам, контакты)
250|- **Допустимые отклонения:** небольшой разброс времени (3-30 мин на сайте — ок), скриншоты в разном формате (PNG/JPG)
251|- **Подозрительные признаки:** время на втором скриншоте раньше первого, отсутствие целевого сайта, скриншоты только поиска без сайта
252|
253|### Нюансы
254|- На UNU нет системы звёзд/рейтинга для отчётов — только «одобрить/отклонить»
255|- 12B vision-модель может ошибаться в деталях, но сайт и время определяет уверенно
256|- При массовой проверке эффективнее открывать URL одобрения напрямую, минуя список отчётов
257|- Если curl возвращает 302 — это не значит успех, нужна браузерная сессия
258|- **ВАЖНО:** одобрение без проверки скриншотов недопустимо. Даже при 17+ отчётах — каждый проверяется индивидуально через vision_analyze. Время проверки 17 отчётов ≈ 5-8 минут (по 2 вызова на отчёт).
259|
260|### Пакетное создание заказов
261|- **Клонирование:** `/tasks/clone/{task_id}` — форма с предзаполненными полями
262|- Менять только название (`browser_type` на e10) и ключ в описании (JS: `$('textarea[name="task_descr"]').val(...).replace(...)`)
263|- Затем `$('button[type="submit"]').first().click()`
264|- **Массовое редактирование цен:** `browser_type` на поле `input[name="task_price"]` + JS-submit
265|- **Массовая оплата:** `/tasks/pay/{id}` → JS: nativeInputValueSetter для поля количества → jQuery trigger → button.click()
266|- Без `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set` React-форма не видит программные изменения

270|## Вход под исполнителем и оценка выполненных заданий
271|
272|### Алгоритм
273|
274|1. **Выйти из текущего аккаунта:** `https://unu.im/account/logout`
275|2. **Зайти на главную** → кнопка «Вход» → `/account/login`
276|3. **Ввести учётные данные:**
277|   - E-mail: `testingkrk@gmail.com`
278|   - Пароль: `orsvmm`
279|4. **Пройти reCAPTCHA** (требуется ручное вмешательство — автоматизация блокируется)
280|5. **Нажать «Войти в мой аккаунт»**
281|6. **Получить сессию:** `document.cookie` → значение `PHPSESSID=...`
282|
283|### Проверка выполненных заданий
284|
285|1. Перейти в «Мои заказы» → найти задачу с выполненными отчётами
286|2. Или напрямую: `/tasks/reports/{task_id}/check` — отчёты на проверку
287|3. Или: `/tasks/reports/{task_id}/done` — уже проверенные отчёты
288|4. Для оценки качества использовать **vision-анализ** (см. раздел «Проверка отчётов»)
289|
290|### Нюансы
291|- **reCAPTCHA** блокирует полностью автоматический вход — нужен живой браузер с ручным прохождением
292|- После прохождения капчи сессия сохраняется в cookies браузера
293|- При смене аккаунта старый PHPSESSID становится невалидным
294|- **Печеньки (🍪):** внутренняя валюта UNU для бонусов, не влияет на вход
295|- Баланс виден в дашборде: `https://unu.im/dashboard`
