1|1|# LLM Wiki (Memex) — Андрей Карпатый
2|2|
3|3|Дата: 17.06.2026
4|4|Источник: GitHub Gist «llm-wiki.md» (4 апреля 2026), отсылка к Vannevar Bush «As We May Think» (1945)
5|5|
6|6|## Ключевая идея
7|7|
8|8|**LLM Wiki** — это паттерн построения персональной базы знаний на LLM. Вместо RAG (поиск по документам при каждом запросе) LLM **инкрементально строит и поддерживает вики** — структурированную, перекрёстно связанную коллекцию markdown-файлов.
9|9|
10|10|> «The wiki is a persistent, compounding artifact. Cross-references are already there. Contradictions have already been flagged. The synthesis already reflects everything you've read.»
11|11|
12|12|Карпатый прямо связывает идею с **Memex** Вэнивара Буша (1945) — персональное, курируемое хранилище знаний с ассоциативными связями между документами. Буш не мог решить проблему «кто будет это обслуживать». LLM решает.
13|13|

16|16|## RAG vs LLM Wiki — ключевое отличие
17|17|
18|18|| | **RAG** | **LLM Wiki** |
19|19||---|---|---|
20|20|| **Как работает** | Поиск чанков при запросе | Знания скомпилированы **заранее** |
21|21|| **Накопление** | Нет — каждый запрос с нуля | Да — вики растёт с каждым источником |
22|22|| **Синтез 5 документов** | Пересобирается каждый раз | Уже сделан, обновляется |
23|23|| **Противоречия** | Не видны | Отмечены при инжесте |
24|24|| **Обслуживание** | Не нужно (нет структуры) | Делает LLM (бесплатно) |
25|25|
26|26|> «Ask a subtle question that requires synthesizing five documents, and RAG has to find and piece together fragments every time. With a wiki — the synthesis already exists.»

30|30|## Архитектура: три слоя
31|31|
32|32|```
33|33|┌─────────────────────────────────────────┐
34|34|│  SCHEMA (CLAUDE.md / AGENTS.md)        │ ← Правила: структура, конвенции, workflows
35|35|├─────────────────────────────────────────┤
36|36|│  WIKI (markdown-файлы)                 │ ← LLM пишет и поддерживает
37|37|│  • entity pages, summaries, synthesis  │
38|38|│  • cross-references, contradictions    │
39|39|├─────────────────────────────────────────┤
40|40|│  RAW SOURCES (неизменяемые)            │ ← Ты собираешь: статьи, PDF, заметки
41|41|└─────────────────────────────────────────┘
42|42|```
43|43|
44|44|- **Raw sources** — неизменяемый источник истины, LLM только читает
45|45|- **Wiki** — LLM владеет полностью: создаёт, обновляет, перекрёстно ссылается
46|46|- **Schema** — документ-инструкция, который делает LLM дисциплинированным вики-редактором, а не болтливым чат-ботом

50|50|## Операции
51|51|
52|52|### 1. Ingest (загрузка)
53|53|Ты добавляешь источник → LLM:
54|54|- Читает источник
55|55|- Обсуждает с тобой ключевые выводы
56|56|- Пишет summary-страницу
57|57|- Обновляет index
58|58|- Обновляет релевантные entity/concept pages (**один источник может затронуть 10-15 страниц**)
59|59|- Добавляет запись в log
60|60|
61|61|> «I prefer to ingest sources one at a time and stay involved — I read the summaries, check the updates, and guide the LLM on what to emphasize.»
62|62|
63|63|### 2. Query (запрос)
64|64|Ты задаёшь вопрос → LLM:
65|65|- Ищет релевантные страницы (сначала index → затем drill-down)
66|66|- Синтезирует ответ с цитатами
67|67|- Форматы: markdown, comparison table, слайды (Marp), график (matplotlib), canvas
68|68|- **Важно**: хорошие ответы сохраняются обратно в вики — не исчезают в истории чата
69|69|
70|70|### 3. Lint (проверка здоровья)
71|71|Периодически LLM проверяет вики на:
72|72|- Противоречия между страницами
73|73|- Устаревшие утверждения (новые источники опровергли)
74|74|- Страницы-сироты (без входящих ссылок)
75|75|- Важные концепты без своей страницы
76|76|- Пропущенные перекрёстные ссылки
77|77|- Пробелы в данных (можно закрыть веб-поиском)
78|78|
79|79|---
80|80|
81|81|## Два специальных файла
82|82|
83|83|### index.md — каталог
84|84|- Каждая страница вики: ссылка + one-line summary + метаданные
85|85|- Сгруппирован по категориям (entities, concepts, sources...)
86|86|- LLM обновляет при каждом ingest
87|87|- При query → LLM читает index → находит нужные страницы → drill-down
88|88|- Работает до ~100 источников / сотен страниц без embedding-based RAG
89|89|
90|90|### log.md — хронология
91|91|- Append-only: ingests, queries, lint passes
92|92|- Формат: `## [2026-04-02] ingest | Article Title`
93|93|- Парсится unix-утилитами: `grep "^## \[" log.md | tail -5`
94|94|- Даёт LLM понимание «что делалось недавно»

100|100|| Домен | Что строится |

120|120|## Почему это работает
121|121|
122|122|> «The tedious part of maintaining a knowledge base is not the reading or thinking — it's the bookkeeping.»
123|123|
124|124|Люди бросают вики, потому что **стоимость обслуживания растёт быстрее ценности**. LLM не скучает, не забывает обновить перекрёстную ссылку и может затронуть 15 файлов за один проход.
125|125|
126|126|**Распределение ролей:**
127|127|- **Человек**: курирует источники, направляет анализ, задаёт вопросы, думает о смысле
128|128|- **LLM**: всё остальное — summarization, cross-referencing, filing, bookkeeping

132|132|## Связь с Memex (1945)
133|133|
134|134|Вэнивар Буш в эссе «As We May Think» описал **Memex** — устройство для хранения и связывания документов ассоциативными тропами (как работает человеческая память). Интернет пошёл другим путём — публичным и хаотичным. LLM Wiki возвращается к видению Буша: **приватное, курируемое, со связями между документами как ценностью первого порядка**. Единственное, чего не хватало в 1945 — кто будет делать обслуживание. LLM закрывает этот пробел.

137|137|
138|138|## Как это соотносится с Hermes
139|139|
140|140|Hermes уже реализует часть этого паттерна:
141|141|- **Memory** = компактная вики (user profile + agent memory)
142|142|- **Skills** = schema (инструкции как действовать)
143|143|- **Obsidian vaults** = raw sources + wiki (testAgregatorArticles, hermesKnowledge)
144|144|- **session_search** = retrieval по истории (аналог log.md)
145|145|
146|146|Разница: Карпатый предлагает **полноценную вики** из сотен страниц, где LLM — главный автор, а Obsidian — IDE для навигации.
