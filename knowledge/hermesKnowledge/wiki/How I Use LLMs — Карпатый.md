6|6|## Ключевая идея
7|7|
8|8|Карпатый рассматривает LLM как **интерактивный инструмент**, а не просто текстовый генератор. Его подход — не «vibe coding», а **системная работа** с моделями через комбинацию инструментов, моделей и персонализации.

12|12|## 1. LLM Council («Совет моделей»)
13|13|
14|14|Карпатый **никогда не полагается на одну модель**. По каждому важному вопросу он спрашивает несколько:
15|15|
16|16|| Модель | Для чего |
17|17||--------|----------|
18|18|| ChatGPT (GPT-4) | Универсальные задачи, deep research |
19|19|| Claude | Код, артефакты, визуальные диаграммы |
20|20|| Gemini | Быстрые фактические ответы |
21|21|| Grok | Сложное рассуждение (reasoning) |
22|22|| Perplexity (DeepSeek R1) | Поиск + видимые цепочки рассуждений |
23|23|
24|24|> «Одна модель может решить быстро, но поверхностно. Другая — медленно, но точно. Я использую их как личный совет директоров.»

28|28|## 2. Thinking Models — когда дать LLM «подумать»
29|29|
30|30|**Thinking models** (reasoning) — модели, которые перед ответом проходят внутреннюю цепочку рассуждений.
31|31|
32|32|### Когда использовать
33|33|- Сложная математика
34|34|- Отладка запутанного кода
35|35|- Задачи с многошаговой логикой
36|36|
37|37|### Когда НЕ использовать
38|38|- Простые фактические вопросы
39|39|- Бытовые запросы (прогноз погоды, рекомендации)
40|40|- Переводы и простые генерации текста
41|41|
42|42|> «Для простого не нужен thinking — он только замедлит. Для сложного — обязателен.»

46|46|## 3. Tool Use — инструменты LLM
47|47|
48|48|Современные LLM — не просто текстовые коробки. Они как швейцарский нож:
49|49|
50|50|### Internet Search
51|51|- Модель сама определяет, когда нужен поиск (специальный search token)
52|52|- Выполняет запрос → загружает результаты в контекст → отвечает с цитатами
53|53|- **Разные модели ведут себя по-разному**: ChatGPT автоматически, Perplexity всегда с поиском, Claude — не поддерживает (на апрель 2024)
54|54|
55|55|### Deep Research
56|56|- Комбинирует множественные поисковые запросы + reasoning
57|57|- Ищет десятки источников → синтезирует отчёт (5-10 минут)
58|58|- Пример: «Расскажи про CAAKG в longevity mix, механизмы действия, токсичность»
59|59|- **Важно**: всегда проверять цитаты — это первый драфт, не финальная истина
60|60|
61|61|### File Uploads
62|62|- Загрузка PDF, документов прямо в контекст
63|63|- Модель конвертирует в токены (изображения теряются)
64|64|- Пример: загрузил анализ крови на 20 страниц → модель расшифровала
65|65|
66|66|### Python Interpreter
67|67|- Модель **генерирует и выполняет** код прямо в чате
68|68|- Строит графики, анализирует данные, отлаживает код
69|69|- «Как младший data analyst, которому не нужно переключаться между окнами»
70|70|
71|71|### Claude Artifacts + Cursor Composer
72|72|- **Artifacts**: интерактивные диаграммы, мини-приложения по текстовому описанию
73|73|- **Cursor Composer**: AI-ассистент в IDE, генерирует/редактирует/визуализирует код

91|91|## 5. Персонализация
92|92|
93|93|### Memory (Память)
94|94|LLM запоминает предпочтения между сессиями. Например, жанры фильмов → будущие рекомендации учитывают это.
95|95|
96|96|### Custom Instructions (Пользовательские инструкции)
97|97|Настройка тона, стиля, уровня детализации **на уровне аккаунта** — инжектятся в каждую сессию.
98|98|
99|99|### Custom GPTs
100|100|Специализированные версии модели под задачу:
101|101|- Языковой тьютор (извлекает лексику, создаёт карточки)
102|102|- Кодинг-помощник с конкретным стилем
103|103|- Few-shot prompting: несколько примеров → модель воспроизводит паттерн
104|104|
105|105|> «Custom GPTs — это как иметь личного ассистента, заточенного именно под твою задачу.»

109|109|## 6. Уроки для начинающих
110|110|
111|111|1. **Пойми токенизацию** — как текст разбивается на токены (OpenAI Tokenizer, Tiktokenizer)
112|112|2. **Следи за контекстным окном** — начинай новый чат при смене темы; переполненный контекст размывает ответы
113|113|3. **Экспериментируй с моделями** — простые задачи на бесплатных, сложные на продвинутых
114|114|4. **Используй внешние инструменты** — поиск, Python, файлы расширяют возможности модели
115|115|5. **Будь в курсе** — экосистема LLM обновляется ежемесячно

119|119|## 7. Техническая база (кратко)
120|120|
121|121|- **Токены**: BPE (Byte-Pair Encoding) — «university» → «uni» + «vers» + «ity»
122|122|- **Спец-токены**: `<|endoftext|>`, `<|user|>`, `<|assistant|>` — разделяют роли в диалоге
123|123|- **Pre-training**: сжатие знаний интернета в параметры («zip-файл на 1 TB»)
124|124|- **Post-training**: supervised fine-tuning + RLHF — придание модели «души»
125|125|- **Context Window**: рабочая память модели, всё общение умещается в последовательность токенов
