16|16|## Полная аналогия: OS → LLM
17|17|
18|18|| Концепт ОС | LLM-эквивалент | Пояснение |
19|19||------------|----------------|-----------|
20|20|| **CPU** | Сама LLM (GPT-4, Claude) | Вычислительное ядро, «думающая» часть |
21|21|| **RAM** | Контекстное окно (128K токенов) | Рабочая память, ограниченный ресурс |
22|22|| **Filesystem** | Векторное хранилище / долгая память | Постоянное хранение, retrieval |
23|23|| **Processes** | Агенты | Изолированные задачи с ограниченным контекстом |
24|24|| **IPC** | Tool calls + handoffs между агентами | Взаимодействие между процессами |
25|25|| **Kernel** | Оркестрация (LangGraph, фреймворки) | Планировщик, управление ресурсами |
26|26|| **User space** | Приложение (твой продукт) | То, с чем взаимодействует пользователь |

40|40|## Три вложенные аналогии (YC 2025)
41|41|
42|42|Карпатый наслаивает три метафоры, каждая со своей предсказательной силой:
43|43|
44|44|### 1. LLM как utility (коммунальная услуга)
45|45|- **Training** = CAPEX (капитальные затраты), как электростанция
46|46|- **Inference** = OPEX (операционные), оплата за токен
47|47|- Требования: низкая задержка, высокий аптайм, стабильное качество
48|48|- Сбой = «блэкаут мирового интеллекта»
49|49|
50|50|### 2. LLM как fab (полупроводниковая фабрика)
51|51|- Огромный R&D CAPEX, глубокие технологические цепочки
52|52|- Жёсткая связка hardware-software
53|53|- Nvidia-GPU облака ↔ fabless дизайнеры, Google TPU ↔ Intel (интегрированная модель)
54|54|
55|55|### 3. LLM как operating system
56|56|- Закрытые лидеры: GPT / Claude / Gemini = Windows / macOS
57|57|- Открытый challenger: Llama = Linux
58|58|- **Следствие**: стартапы строят **на OS**, а не против неё

73|73|## Практические следствия для архитектуры
74|74|
75|75|Команда FRE|Nxt Labs использует эту аналогию в архитектурных ревью. Если агентная система спроектирована без оглядки на OS-принципы — она обречена:
76|76|
77|77|| Ошибка | OS-диагноз |
78|78||--------|-----------|
79|79|| Каждый агент видит всю историю | «Неограниченная RAM на процесс» |
80|80|| Единый реестр инструментов для всех | «Нет разграничения прав» |
81|81|| Нет трейсинга | «Ядро без логов» |
82|82|| Зависимость от глобального состояния | «Однопоточная программа без изоляции» |
83|83|
84|84|> «Ты написал однопоточную программу с глобальным состоянием и без логирования. Оно работает — пока не сломается. А когда сломается — ты не сможешь отладить.»

88|88|## Боевой пример: InterviewLM
89|89|
90|90|Реализация LLM OS на практике (FRE|Nxt Labs):
91|91|
92|92|- **CPU scheduling**: Claude Opus для сложного (координация агентов), Claude Haiku для простого (форматирование)
93|93|- **Memory paging**: каждый агент-интервьюер получает только релевантный контекст на текущий ход. Полный транскрипт — в долгом хранилище. 90%+ cache hit rate.
94|94|- **Checkpointing**: LangGraph сохраняет состояние на каждом узле — можно перезапустить с последней успешной точки
95|95|- **Process isolation**: сессия кандидата = изолированный LangGraph-ран. Сбой одной сессии не затрагивает другие
96|96|- **Kernel instrumentation**: каждый шаг агента → LangSmith trace. Можно воспроизвести любую продакшен-сессию
97|97|
98|98|**Результат**: 8 агентов, 100+ одновременных сессий, −40% стоимости, p99 < 2 сек.

102|102|## Software 3.0 — развитие идеи
103|103|
104|104|К 2025 году Карпатый расширил картину до трёх парадигм:
105|105|
106|106|| Парадигма | Субстрат | Кто пишет | Инструменты |
107|107||-----------|----------|-----------|-------------|
108|108|| **Software 1.0** | Исходный код | Человек (Python, C++) | IDE, компиляторы, GitHub |
109|109|| **Software 2.0** | Веса нейросети | Оптимизатор (на данных) | PyTorch, Hugging Face |
110|110|| **Software 3.0** | LLM-промпты | Человек (на английском) | Промпты, контекст, агенты |
111|111|
112|112|### Ключевые утверждения
113|113|1. **Субстрат пожирает субстрат**: 2.0 ест 1.0 (Tesla Autopilot: C++ → веса), 3.0 начинает есть 2.0 (промпты оркестрируют модели)
114|114|2. **Все теперь программисты**: английский — новый язык программирования
115|115|3. **Сложность не в коде**: написать код легко; DevOps (Apple Dev ID, платежи, хостинг) — вот где неделя работы
116|116|4. **LLM станут компилятором для 2.0**: llm.c — подготовка к миру, где LLM генерирует низкоуровневый код по запросу
