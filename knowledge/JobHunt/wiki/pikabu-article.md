# Я 15 лет в IT, и меня достало делать «кнопочки». Пошёл на hh.ru, пересчитал все вакансии и выбрал бэкенд. Спойлер: PHP ещё жив

Всем привет. Меня зовут Сергей, я из Ульяновска. В IT болтаюсь с середины 2000-х — начинал с jQuery, ExtJS, Backbone, первых версий Angular. Но коммерческий фронтенд у меня последние ~3 года: React, TypeScript, финтех.

Казалось бы — сиди, радуйся. Зарплата капает, удалёнка, тапочки. Но полгода назад поймал себя на мысли: **я упёрся в потолок**. Не в зарплатный — в профессиональный.

Понимаете, это чувство, когда ты делаешь формочки и кнопочки. Пусть сложные, с анимациями, микрофронтендами, стейт-машинами — но блин, 15 лет кнопочки. Хочется понимать, что там, **под капотом**. Как данные попадают в базу. Почему API тормозит. Можно ли самому поднять сервис от идеи до продакшена, не дёргая бэкендера за рукав.

Fullstack, короче. Звучит солидно. Осталось понять — **какой бэкенд учить**.

**PHP вырвался в лидеры fullstack.** Я сам удивился, но цифры есть цифры. Почему так?

В PHP-экосистеме исторически сложилась культура fullstack. Laravel даёт из коробки и бэкенд, и шаблонизатор Blade. Один разработчик часто делает всё — от базы до вёрстки. Плюс тонны проектов (интернет-магазины, CRM), где нужен «и швец, и жнец».

**Go — 2 fullstack-вакансии.** Это не баг, а фича. Go создан для высоконагруженных микросервисов, а не для fullstack. Когда компании нужен fullstack на Go — это экзотика.

## React + бэкенд: вот где Node.js показывает зубы

Теперь — самое важное для меня и, думаю, для большинства фронтендеров. Какие бэкенды реально ищут в связке с React?

> 📊 **[ВСТАВИТЬ КАРТИНКУ: react_combos.png]**

- **React + Node.js — 16 вакансий**
- **React + PHP — 9**
- **React + Python — 8**
- **React + Java — 6**
- **React + .NET — 5**
- **React + Go — 1**

**Node.js — двукратный отрыв.** 16 против 9 у ближайшего конкурента. Это не случайность, а системный паттерн.

Почему это логично:
1. **Один язык везде.** TypeScript на фронте и на бэке. Типы переиспользуются, не надо переключаться между синтаксисами.
2. **Next.js как точка сборки.** API routes, Server Components, Server Actions — любой Next.js-разработчик уже немножко fullstack.
3. **NestJS для взрослых.** Модульная архитектура, DI, guards, interceptors — прям как нормальный бэкенд-фреймворк, только на TypeScript.
4. **Единая экосистема.** Zod для валидации, date-fns для дат — работает и там, и там. Shared-библиотеки в монорепе без дублирования.

**React + PHP (9 вакансий)** — обычно Laravel в бэкенде и React как админка/SPA. Рабочая связка, особенно в e-commerce. Но готовьтесь переключаться между мирами JS и PHP.

**React + Python (8)** — Django REST или FastAPI на бэке. Хорошо, если проект завязан на AI/ML-экосистему. Но таких меньше, чем чисто веб-приложений.

**React + Go (1)** — если вы встретили эту вакансию, напишите в комментах, очень интересно.

## Что я выбрал и почему

Хватит цифр. Личное решение.

После двух недель копания в hh.ru, десятков табличек и трёх литров кофе я выбрал: **Node.js + NestJS + TypeScript.**

Аргументы — не «потому что модно», а потому что цифры сошлись с моим бэкграундом:

1. **Один язык — одно сознание.** Я пишу на TypeScript больше пяти лет. Декораторы `@Controller()`, `@Injectable()` в NestJS — это продолжение моего опыта, а не новый мир.

2. **16 вакансий React + Node.js — лидер с отрывом.** Мне не надо убеждать работодателя, что я могу писать бэкенд на TypeScript — они сами этого хотят.

3. **Низкий порог входа, высокий потолок.** Простой CRUD на NestJS делается за вечер. А дальше — CQRS, event-driven, микросервисы на Kafka. Расти есть куда.

4. **Next.js как трамплин.** Я уже работаю с Next.js на фронте. Server Actions, API Routes — это тот же fullstack, просто на одном фреймворке.

5. **Единая кодовая база.** Типы, валидация, утилиты — всё общее. Никаких «забыл обновить типы на фронте после изменения API».

Когда освою бэкенд до уверенного senior-уровня, вторым языком возьму **Python + FastAPI** — как мост в AI/ML-проекты. Фронтендер, который понимает машинное обучение — редкая и дорогая комбинация.

## Что делать вам: практические рекомендации (без воды)

### Если ты React/TypeScript-фронтендер
→ **Node.js, NestJS / Next.js API routes.** Язык уже знаешь, синергия максимальная, вакансий больше всех в связке с React.

### Если data-сайентист или метишь в AI
→ **Python, FastAPI или Django.** Строить веб-приложения вокруг ML-моделей — редкий и ценный навык.

### Если работаешь в enterprise
→ **Java (Spring Boot) или C# (.NET).** Банки, телеком, госсектор. Стабильно, надёжно, высокий чек. Но порог входа выше.

### Если любишь хардкор и highload
→ **Go.** Идеален для микросервисов, сетевых демонов, Kubernetes-операторов. Но fullstack-вакансий почти нет — придётся идти в чистый бэкенд.

### Если нужно максимальное число вакансий прямо сейчас
→ **PHP + Laravel.** 30 fullstack-вакансий — больше всех. Но переход из TypeScript-мира потребует культурной адаптации.

## Главные уроки, которые я вынес

1. **Node.js — самый логичный выбор для React-фронтендера.** 16 вакансий React + Node против 1 у React + Go. Разница в 16 раз — это сигнал рынка, а не погрешность.

2. **Fullstack — не для новичков.** 61 senior → 24 middle. Работодатели хотят глубину, а не ширину. Сначала станьте сильным в чём-то одном.

3. **Один язык на клиенте и сервере — конкурентное преимущество.** TypeScript везде: типы, валидация, тулинг — всё быстрее и надёжнее.

4. **Данные > хайп.** Каждый месяц выходит статья «Почему язык X — будущее». Мог бы пойти учить Rust, Zig, Gleam. Но цифры с hh.ru говорят другое. Я послушал цифры, а не блогеров.
